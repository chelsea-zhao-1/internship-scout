## What this project does

Internship Scout is a scheduled pipeline that monitors company job boards for new internship postings and sends Gmail alerts. It runs daily via GitHub Actions at 12:00 UTC and commits updated state back to the repo automatically.

## Commands

```bash
# Setup
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# One-time Gmail OAuth setup (generates token.json)
python setup_gmail.py

# Run the pipeline locally
GMAIL_CREDENTIALS=$(cat credentials.json) GMAIL_TOKEN=$(cat token.json) NOTIFY_EMAIL=you@example.com python main.py

# Run tests
pytest tests/
pytest tests/test_pipeline.py::TestFilter  # single class
pytest tests/test_pipeline.py::TestFilter::test_intern_title_matches  # single test
```

## Architecture

The pipeline runs in four stages, one per module:

1. **`adapters/`** — Fetch and normalize raw job data from ATS APIs. `greenhouse.py` hits `https://boards-api.greenhouse.io/v1/boards/{token}/jobs`, normalizes each job to `{id, title, location, url, updated_at, source}`, and deduplicates by `id` across multiple boards. Adding a new ATS means adding a new adapter here and registering it in `ATS_ADAPTERS` in `main.py`.

2. **`pipeline/filter.py`** — Filters normalized jobs to intern roles. Currently a simple `"intern" in title.lower()` match. Note: "Internal Audit Analyst" is a known false positive, accepted by design.

3. **`pipeline/diff.py`** — Computes new roles by comparing current job IDs against IDs stored in `state.json`. Roles that disappear from the board are silently dropped (no removal alerts).

4. **`notify/gmail.py`** — Sends emails via the Gmail API. Reads `GMAIL_CREDENTIALS` and `GMAIL_TOKEN` from environment variables (JSON strings). `NOTIFY_EMAIL` sets the recipient.

**`main.py`** orchestrates these stages. The key invariant: **state is never updated unless the email send succeeds**. If Gmail fails, the run exits with status 1 and the roles will be re-detected next run.

## State management

`state.json` is the persistence layer, committed to the repo by the GitHub Actions workflow after each run. Its structure:

```json
{
  "last_checked": "<ISO timestamp>",
  "last_status": "success | fetch_error | notify_error",
  "sources": {
    "<source_name>": {
      "last_checked": "<ISO timestamp>",
      "roles": {
        "<job_id>": { "title", "location", "url", "updated_at", "first_seen" }
      }
    }
  }
}
```

A missing or unparseable `state.json` triggers a **cold start**: a bootstrap email listing all current intern roles is sent, and state is initialized. This prevents false "new role" alerts on first run.

## Adding a new company to monitor

Add an entry to `sources.yaml`:

```yaml
sources:
  - name: stripe          # used as the state key
    display_name: Stripe  # used in email subjects/bodies
    ats: greenhouse
    boards:
      - stripe
```

The `boards` list supports multiple Greenhouse board tokens for the same company (jobs are deduplicated by ID across boards).

## GitHub Actions secrets required

| Secret | Value |
|--------|-------|
| `GMAIL_CREDENTIALS` | Contents of `credentials.json` (Google OAuth client) |
| `GMAIL_TOKEN` | Contents of `token.json` (generated by `setup_gmail.py`) |
| `NOTIFY_EMAIL` | Recipient email address |
